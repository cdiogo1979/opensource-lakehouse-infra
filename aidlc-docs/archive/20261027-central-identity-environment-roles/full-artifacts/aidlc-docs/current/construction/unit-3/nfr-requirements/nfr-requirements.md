# NFR Requirements — Hive Metastore and Direct Spark Authorization

## Scope and assumptions

These requirements apply to direct Spark authorization against Hive Metastore (HMS) metadata and RustFS objects. The approved functional matrix and locations remain authoritative. The target is the existing local Docker Compose proof of concept with the approved human/service identities and three environment buckets. This document adds quality, reliability, security, audit, and verification constraints; it does not change role permissions or authorize implementation.

The selected assumptions are fixed PoC scale, no latency/availability SLA, bounded operations and retries, fail-closed behavior, measured revocation delay, per-human identity isolation, sanitized operational evidence, a reviewed preservation inventory before later changes, and pinned component versions. The user accepts cross-environment metadata visibility. Authorization correctness is required at the RustFS object boundary for direct Spark reads/writes. HMS metadata DDL authorization is not guaranteed and remains an explicit limitation. All allow/deny tests use disposable databases, tables, and objects.

## Architecture acceptance gate

The current HMS configuration uses `StorageBasedAuthorizationProvider`; the design research indicates this provider bases decisions on filesystem permissions, whereas S3A reports stub permissions and does not enforce access against those stubs. The user accepts metadata visibility, so metadata confidentiality is not a release gate. Actual Spark reads and writes must still be enforced by per-user RustFS credentials. This NFR does not claim protection against analyst Hive metadata DDL; add an HMS authorization component only through a separately approved architecture change if that protection is required.

## Traceability

- HMS-NFR-01–02: fixed local PoC scope and correctness-first behavior.
- HMS-NFR-03–06: fail-closed dependency handling, authorization correctness, identity consistency, and measured revocation.
- HMS-NFR-07–10: credential isolation, internal network boundary, least privilege, and safe audit evidence.
- HMS-NFR-11–12: preservation, recovery, and safe errors.
- HMS-NFR-13–14: compatibility control and disposable evidence.
