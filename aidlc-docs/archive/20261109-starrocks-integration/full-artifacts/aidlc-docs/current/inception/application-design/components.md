# Components — StarRocks Integration

| ID | Component | Location | Responsibility |
|---|---|---|---|
| C1 | StarRocks runtime | `docker-compose.starrocks.yml`, `infra/starrocks/conf/{fe,be}.conf` | One FE and one BE from the upstream `starrocks/fe-ubuntu` and `be-ubuntu` 4.1.7 images, pinned by digest. Loopback ports, named volumes, memory limits, health checks. No custom image build (AD-Q2: A). |
| C2 | Keycloak identities | `infra/keycloak/realm-contract.json`, `bootstrap-realm.py` | The new confidential client `srv-starrocks` (service account only, a member of `role-default-writer`, Polaris role mapper). The new client `starrocks` (password grant, an audience mapper `aud=starrocks`, the `preferred_username` claim) for user login tokens. |
| C3 | Runtime credentials | `scripts/prepare-lakehouse-runtime.py` | Creates `starrocks-root-password` and `srv-starrocks-client-secret` once, at mode 0600, and stages read-only copies for the containers that need them. |
| C4 | StarRocks bootstrap | `infra/starrocks/bootstrap-starrocks.py` | Idempotent and refuses on conflict. Sets the root password on first run, registers the BE, and creates the three Iceberg REST catalogs (OAuth2 as `srv-starrocks`, vended credentials), the five roles and their grants, and the three MV databases (AD-Q1: A, AD-Q3: A). |
| C5 | StarRocks user reconciler | `infra/starrocks/reconcile-starrocks-users.py` | Reads Keycloak product-group memberships and current StarRocks users and grants. Plans and applies the changes: create JWT users, grant and revoke roles, set default roles, and remove users who left all product groups. It has two SQL transports: `docker exec` on the host, and the network MySQL client in the scheduled container. |
| C6 | Scheduled reconciler | `infra/polaris/reconciler/{Dockerfile,run.sh}`, `docker-compose.yml` | The existing `polaris-group-reconciler` image gains a MySQL client and C5. Each cycle runs the Polaris reconcile, then the StarRocks reconcile when `STARROCKS_ENABLED` is not `false` (follow-up 1: B). |
| C7 | Login helper | `scripts/starrocks-login.sh` | Asks for the Keycloak password, gets a token from the `starrocks` client, writes it to a private temporary file, and opens a MySQL 9.x client session (container) with the OpenID Connect client plugin. It never prints the token. |
| C8 | Platform lifecycle | `scripts/lakehouse.sh`, `scripts/reset-lakehouse.py`, `scripts/bootstrap-default-product.sh`, `.env.example`, `docker-compose.deferred.yml` | Includes the StarRocks file in start, status, and stop unless `STARROCKS_ENABLED=false`, and adds `reconcile-starrocks`. The reset inventory gains the StarRocks volumes and network. The product bootstrap calls C4 and C5. The deferred inventory is updated. |
| C9 | Polaris principal reconcile | `infra/polaris/reconcile-keycloak-groups.py` | Confirmed in design: the existing reconciler creates a principal for every group member, and Keycloak's group-members endpoint includes service-account users. So `service-account-srv-starrocks` gets its principal and `role-default-writer` with no code change; only a contract test is added. |
| C10 | Legacy retirement | `infra/starrocks/{fe,be,kerberos,ldap-access,sql-bootstrap,preflight}`, `infra/starrocks/conf/{core-site,hive-site}.xml`, `scripts/bootstrap-starrocks-sql.sh` | Removed from the active tree; they are preserved in the intent archive. |
| C12 | SQL TLS (added in Build and Test) | `scripts/prepare-starrocks-certificates.py`, `infra/starrocks/fe-entrypoint.sh` | Local CA and FE certificate (SAN `starrocks-fe`, `localhost`, `127.0.0.1`) and a PKCS12 keystore with a protected password. The FE entrypoint adds `ssl_keystore_*` settings to the tracked `fe.conf`, so JWT logins use verified TLS. |
| C11 | Docs and tests | `README.md`, `tests/starrocks/` | README sections, contract tests, and property-based tests for the pure planners in C4 and C5. |
